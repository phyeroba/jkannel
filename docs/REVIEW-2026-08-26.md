# Review list — 2026-08-26

Peter's walkthrough of the running console. Nothing is ticked here on the
strength of a code change; each one is ticked because a measurement or a test
said so, and the measurement is named.

## Dialogs that were squashed

All three had the same cause. The field grid was ported from the kit's own Add
SMSC dialog byte for byte — `repeat(auto-fit, minmax(200px, 1fr))` — but the
kit's card is 620px and ours is 900px for a create form, so the same rule gives
two 283px tracks there and four 205px ones here. A label, a control and a hint
do not fit in 205px. The minimum is now the width the kit RENDERS.

- [x] **Carriers → New carrier** — 205px tracks → 423px.
- [x] **Recipient Policy → New entry** — same.
- [x] **Customers → Add customer** — same. Two customers seeded while there.
- [x] Every dialog opened in Playwright and measured, rather than the markup
      being trusted: `scripts/dialog-audit.mjs`. **Including the EDIT dialogs** —
      "same to editing a new carrier" went unmeasured at first because the audit
      only opened the create ones. All eleven pass.

## Grids missing pagination / filtering / sorting

- [x] **Messages** — pages 17,689 rows now. Adding `offset` was not enough: the
      repository uses keyset paging when no offset is sent and returns
      `total: null`, so omitting `offset=0` left page one with no total and Next
      permanently disabled. It reported "Showing 1–100 of 100".
- [x] **Log Explorer → Entries** — `offset` added to the ring buffer, the
      controller and the view. Pages the whole match, 100 at a time. **Sortable**
      on Time, Level, Component, Route, Status and Duration, ordered on the
      SERVER: sorting the rows the browser happens to hold would order one page
      against itself, so "slowest first" would show the slowest request on the
      page you are on rather than the slowest there is. Level orders by severity,
      not alphabetically.
- [x] **SMPP Errors → Command status reference** — already filterable by search,
      and it shows "18 of 18": that is the complete reference this build can
      describe, so there is no page two to add.

## Errors on screen

- [x] **Reports / API Gateway — "too many authentication attempts"**. Never
      reproduced (Redis holds no bucket), but the cause is understood and the
      message is fixed. The limiter counts failed SIGN-INS and failed token
      refreshes; once it trips it blocks the refresh every screen depends on, so
      whichever screen is open appears to be the broken one. The server already
      knew how long it would last — `retryAfterSeconds` in the exception and a
      `Retry-After` header — and the filter discarded the first while nothing
      read the second. Both surfaced now, worded as a sign-in lockout.

## End-to-end behaviour, proved rather than assumed

- [x] **Backup and restore** — two separate findings. `BACKUP_ENCRYPTION_KEY`
      was never set, so every real backup would have failed (loudly and with an
      exact message, to its credit). Key generated: a real backup is now a 3.5MB
      AES-256-GCM pg_dump in 2.2 seconds, and Verify decrypts it and reads 1034
      entries out of `pg_restore --list`. Separately, the deprecated
      `POST /backups` recorded a row-count manifest as `completed`, `encrypted`,
      with a size and a checksum and NO artifact — indistinguishable in the
      register from a real backup, next to a Restore button. It now refuses and
      names the endpoint that works.
- [x] **Content filtering** — proved on the real send path by
      `scripts/policy-e2e.mjs`: a message carrying the phrase is refused 403, the
      same destination without it is accepted, and removing the rule lets it
      through.
- [x] **Blacklist / whitelist** — both exist, plus DND. A blacklisted number is
      refused by the send path, not merely by the preview; an unlisted number
      still gets through while the entry exists, so an outage cannot pass as a
      working block.
- [x] **Recipient Policy** — the whole workflow, same script.
- [x] **Inbound routing** — `scripts/inbound-e2e.mjs`: an MO message matches its
      rule, fans out to the configured destination, and is idempotent on retry.
      **NOTE**: this deployment has ZERO MO rules of its own, so real inbound
      traffic currently matches nothing and is stored unrouted.
- [x] **Customers** — Stanbic Bank Uganda and Umeme Ltd seeded.

## Found in the second pass

- [x] **The Backup screen showed "An internal error occurred" on every visit.**
      `@Get(':id')` was declared above `@Get('schedules')`, and Nest matches in
      declaration order — so `GET /backup-dr/schedules` reached the single-record
      handler, passed the word "schedules" to a uuid column, and answered 500.
      The method carried a comment asserting it was declared AFTER the literal
      paths, which was untrue of its own file, so reading the code confirmed the
      bug rather than revealing it. It named itself on the first try once the
      exception filter began logging causes. `scripts/route-shadow-audit.mjs`
      now checks all 353 routes; this was the only one.
- [x] **A status badge in a dot-sized column.** `.health-list` reserves 18px for
      the kit's round indicator; Services puts a ~59px badge there, losing 41px
      of every row on Dependencies.
- [x] **`overflow-audit` was over-reporting by two orders of magnitude.** It
      counted anything wider than its own box, but spilling is not clipping:
      `.table-wrap` bleeds a table to the panel edge with negative margins BY
      DESIGN, and a scrolling ancestor means the content is reachable. Corrected
      to ask whether content reaches past something that actually cuts it off.
      422 findings became 4, then 0.
- [x] **A flaky wall-clock performance test.** `perSendMs < 2` failed at 3.07ms
      on a machine that was building containers and passed alone a minute later.
      It now compares 500 rules against 10 measured in the same run, which
      cancels out how busy the machine is and still catches the thing it exists
      for — a scan that stops being linear.
